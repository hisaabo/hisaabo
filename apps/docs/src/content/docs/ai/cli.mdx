The Hisaabo CLI (`hisaabo`) brings your entire business management workflow to the terminal. It is useful for three things: quick lookups without opening a browser, automation scripts and cron jobs, and AI agent workflows that execute shell commands as part of a broader pipeline.

Every command outputs clean JSON by default, making it straightforward to pipe into `jq`, `mail`, `curl`, or any other Unix tool.

---

## Installation

```bash
npm install -g @hisaabo/cli
```

Verify the installation:

```bash
hisaabo --version
```

## Authentication

### Login

```bash
hisaabo login --api-url https://your-hisaabo-instance.com
```

The CLI prompts for your email and password, authenticates against your Hisaabo instance, and stores the session token in `~/.hisaabo/credentials.json`. For headless environments (servers, CI), pass credentials directly:

```bash
hisaabo login --api-url https://your-hisaabo-instance.com \
              --email owner@yourshop.in \
              --password yourpassword
```

Session tokens last 30 days. After expiry, run `hisaabo login` again to refresh.

### Environment variables (recommended for automation)

Rather than logging in interactively, set credentials as environment variables. This is the preferred approach for cron jobs and CI/CD pipelines:

```bash
export HISAABO_API_URL=https://your-hisaabo-instance.com
export HISAABO_API_KEY=hisaabo_key_xxxxxxxxxxxxxxxxxx
export HISAABO_BUSINESS_ID=biz_xxxxxxxxxxxxxxxxxx
```

### Select active business

If your account manages multiple businesses:

```bash
# List all businesses on your account
hisaabo business list

# Set the active business for all subsequent commands
hisaabo business use biz_xxxxxxxxxxxxxxxxxx

# Or pass --business on any command to override
hisaabo dashboard --business biz_xxxxxxxxxxxxxxxxxx
```

### Check current context

```bash
hisaabo whoami
# Output:
# Logged in as: owner@yourbusiness.com
# API URL:      https://your-hisaabo-instance.com
# Business:     Sharma Traders (biz_xxxxxxxxxxxxxxxxxx)
```

## Command Reference

### `hisaabo dashboard`

Display key business metrics.

```bash
hisaabo dashboard
hisaabo dashboard --period today
hisaabo dashboard --period this-week
hisaabo dashboard --period this-month
hisaabo dashboard --period last-month
hisaabo dashboard --period this-year
hisaabo dashboard --from 2026-01-01 --to 2026-03-31
```

**Options:**
| Flag | Description |
|---|---|
| `--period` | Predefined period: `today`, `this-week`, `this-month`, `last-month`, `this-year` |
| `--from` | Start date (ISO 8601) for custom period |
| `--to` | End date (ISO 8601) for custom period |
| `--json` | Output raw JSON instead of formatted table |

**Example output:**

```
Business Dashboard — March 2026
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Revenue:        ₹4,82,500
Expenses:       ₹1,23,400
Net Profit:     ₹3,59,100
Outstanding:    ₹78,250 (6 overdue invoices)

Top customers this month:
  Gupta Enterprises      ₹1,42,000
  Sharma Traders         ₹98,500
  Vinod & Sons           ₹67,000

Low stock alerts: 3 items
```

### `hisaabo invoice`

#### `hisaabo invoice list`

```bash
hisaabo invoice list
hisaabo invoice list --status overdue
hisaabo invoice list --status paid
hisaabo invoice list --party "Sharma Traders"
hisaabo invoice list --from 2026-03-01 --to 2026-03-31
hisaabo invoice list --status overdue --sort oldest-first
hisaabo invoice list --type purchase
```

**Options:**
| Flag | Description |
|---|---|
| `--status` | Filter: `draft`, `sent`, `paid`, `overdue`, `cancelled` |
| `--type` | Invoice type: `sale` (default) or `purchase` |
| `--party` | Party name or ID |
| `--from` / `--to` | Date range filter |
| `--sort` | Sort order: `newest-first` (default), `oldest-first`, `amount-asc`, `amount-desc` |
| `--limit` | Maximum results (default 50, max 100) |
| `--json` | Raw JSON output |

#### `hisaabo invoice get`

```bash
hisaabo invoice get BB-12948
hisaabo invoice get inv_xxxxxxxxxx
```

#### `hisaabo invoice create`

```bash
hisaabo invoice create \
  --party "Montu Arora" \
  --item "Spinach" --quantity 7.3 --unit kg --price 65 \
  --item "Tomato" --quantity 5 --unit kg --price 40 \
  --date 2026-03-26 \
  --due-date 2026-04-10
```

For complex invoices with many line items, pass a JSON file:

```bash
hisaabo invoice create --from-file invoice.json
```

Where `invoice.json` follows the format:

```json
{
  "party": "Gupta Enterprises",
  "date": "2026-03-26",
  "dueDate": "2026-04-10",
  "items": [
    { "item": "Basmati Rice 25kg", "quantity": 10, "unit": "bag", "price": "1250.00" },
    { "item": "Mustard Oil 15L", "quantity": 5, "unit": "can", "price": "2100.00" }
  ],
  "notes": "Delivery to warehouse on 28th"
}
```

#### `hisaabo invoice pdf`

```bash
# Download PDF to current directory
hisaabo invoice pdf BB-12948

# Specify output path
hisaabo invoice pdf BB-12948 --output /tmp/invoices/

# Thermal (58mm) format
hisaabo invoice pdf BB-12948 --format thermal
```

## Power User Workflows

These are the workflows that separate a Hisaabo user from a Hisaabo power user. All copy-paste ready.

### Morning business check with jq

Start every workday with a clear picture. This one-liner pulls your dashboard, formats it, and prints only what matters:

```bash
hisaabo dashboard --period today --json | jq -r '
"=== TODAY (" + (now | strftime("%d %b %Y")) + ") ===
Revenue:       \(.totalRevenue)
Outstanding:   \(.totalOutstanding) (\(.overdueCount) overdue)
Invoices:      \(.invoiceCount)

Top customers:
\(.topCustomers[:3] | .[] | "  \(.name): \(.revenue)")"
'
```

For a richer morning brief, combine it with overdue and low-stock data:

```bash
#!/bin/bash
# morning-brief.sh

DASH=$(hisaabo dashboard --period today --json)
OVERDUE=$(hisaabo invoice list --status overdue --sort oldest-first --limit 5 --json)
LOW=$(hisaabo item list --low-stock --json)

echo "=== MORNING BRIEF — $(date +"%d %b %Y") ==="
echo ""
echo "Revenue today:    $(echo $DASH | jq -r '.totalRevenue')"
echo "Outstanding:      $(echo $DASH | jq -r '.totalOutstanding')"
echo ""

OVERDUE_COUNT=$(echo $OVERDUE | jq 'length')
if [ "$OVERDUE_COUNT" -gt 0 ]; then
  echo "OVERDUE ($OVERDUE_COUNT):"
  echo $OVERDUE | jq -r '.[] | "  \(.invoiceNumber) — \(.party.name) — ₹\(.totalAmount) (\(.daysOverdue) days)"'
  echo ""
fi

LOW_COUNT=$(echo $LOW | jq 'length')
if [ "$LOW_COUNT" -gt 0 ]; then
  echo "LOW STOCK ($LOW_COUNT):"
  echo $LOW | jq -r '.[] | "  \(.name): \(.stockQuantity) \(.unit) left"'
fi
```

### Automated GST filing prep

Run this on the 28th of every month. It exports GSTR-1 data, generates the 3B summary, and emails everything to your CA — no manual steps.

```bash
#!/bin/bash
# gst-filing-prep.sh — run monthly on the 28th via cron
# 0 8 28 * * /opt/hisaabo/gst-filing-prep.sh

MONTH=$(date +%m)
YEAR=$(date +%Y)
CA_EMAIL="ca@yourca.com"
OWNER_EMAIL="owner@yourbusiness.com"
OUTPUT_DIR="/var/gst-reports/${YEAR}-${MONTH}"
mkdir -p "$OUTPUT_DIR"

echo "Preparing GST filing data for ${YEAR}-${MONTH}..."

# Export GSTR-1 (full B2B, B2C, HSN breakdown)
hisaabo gst export \
  --type gstr1 \
  --month "$MONTH" \
  --year "$YEAR" \
  --format json \
  --output "$OUTPUT_DIR/gstr1.json"

# Export GSTR-3B summary
hisaabo gst export \
  --type gstr3b \
  --month "$MONTH" \
  --year "$YEAR" \
  --format csv \
  --output "$OUTPUT_DIR/gstr3b.csv"

# Generate human-readable summary
SUMMARY=$(hisaabo gst summary --period last-month)

# Email to CA with attachments
{
  echo "Hi,"
  echo ""
  echo "GST data for ${YEAR}-${MONTH} is attached. Summary below:"
  echo ""
  echo "$SUMMARY"
  echo ""
  echo "Files:"
  echo "  gstr1.json — B2B/B2C invoice data for GSTR-1 upload"
  echo "  gstr3b.csv — 3B summary for quick review"
  echo ""
  echo "Please review and file before the 11th."
} | mail -s "GST Data ${YEAR}-${MONTH} — Please file by 11th" \
  -a "$OUTPUT_DIR/gstr1.json" \
  -a "$OUTPUT_DIR/gstr3b.csv" \
  "$CA_EMAIL"

# Notify owner
echo "GST filing prep done. Data sent to $CA_EMAIL." | \
  mail -s "GST prep complete for ${YEAR}-${MONTH}" "$OWNER_EMAIL"
```

### Stock reorder alerts via cron

Check twice daily. Alert only when action is needed. The script formats the output as a clean order list, ready to forward to your supplier.

```bash
#!/bin/bash
# stock-reorder-alert.sh — run twice daily: 9 AM and 5 PM
# 0 9,17 * * * /opt/hisaabo/stock-reorder-alert.sh

LOW_STOCK=$(hisaabo item list --low-stock --json)
COUNT=$(echo "$LOW_STOCK" | jq 'length')

if [ "$COUNT" -eq 0 ]; then
  exit 0
fi

# Build reorder list
REORDER_LIST=$(echo "$LOW_STOCK" | jq -r '
.[] | "  \(.name)
       Current: \(.stockQuantity) \(.unit)
       Minimum: \(.lowStockThreshold) \(.unit)
       Suggest reordering: \((.lowStockThreshold * 3 | floor)) \(.unit)"
')

{
  echo "STOCK ALERT — $(date +"%d %b %Y, %I:%M %p")"
  echo "━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━"
  echo ""
  echo "$COUNT items need reordering:"
  echo ""
  echo "$REORDER_LIST"
  echo ""
  echo "View in dashboard: https://your-hisaabo-instance.com/inventory"
} | mail -s "Stock Alert: $COUNT items low — $(date +"%d %b")" \
  owner@yourbusiness.com
```

### Outstanding balance aging report

Run this weekly and know exactly which receivables are at risk before they become bad debt.

```bash
#!/bin/bash
# aging-report.sh — run every Monday morning

OVERDUE=$(hisaabo invoice list --status overdue --sort oldest-first --json)

echo "$OVERDUE" | jq -r '
"RECEIVABLES AGING — " + (now | strftime("%d %b %Y")) + "
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

" + (
  group_by(.party.name) |
  .[] |
  "Party: \(.[0].party.name)
  Total outstanding: ₹\([.[].totalAmount | tonumber] | add | tostring)
  Oldest invoice: \(sort_by(.date) | .[0].invoiceNumber) (\(sort_by(.date) | .[0].daysOverdue) days)\n"
)
'
```

## Scripting Patterns

### Process JSON output with jq

```bash
# Sum total outstanding across all overdue invoices
hisaabo invoice list --status overdue --json | \
  jq '[.[].totalAmount | tonumber] | add'

# List items that need reordering with their stock levels
hisaabo item list --low-stock --json | \
  jq '.[] | "\(.name): \(.stockQuantity) \(.unit) (min: \(.lowStockThreshold))"'

# Get the top 5 customers by outstanding balance
hisaabo party list --outstanding --json | \
  jq 'sort_by(.outstandingBalance | tonumber) | reverse | .[0:5] | .[] | "\(.name): ₹\(.outstandingBalance)"'
```

### Use exit codes in shell scripts

The CLI exits with code `0` on success and non-zero on failure. Use this in conditional logic:

```bash
#!/bin/bash
if hisaabo invoice get "$INVOICE_ID" --quiet; then
  echo "Invoice $INVOICE_ID found"
else
  echo "Invoice $INVOICE_ID not found — check ID" >&2
  exit 1
fi
```

### Chaining commands

```bash
# Create invoice and immediately download the PDF
INVOICE_ID=$(hisaabo invoice create \
  --party "Montu Arora" \
  --item "Spinach" --quantity 7.3 --unit kg --price 65 \
  --json | jq -r '.id')

hisaabo invoice pdf "$INVOICE_ID" --output /tmp/
echo "Invoice PDF saved to /tmp/${INVOICE_ID}.pdf"
```

## For AI Agent Developers

The CLI and MCP server are designed to complement each other. Understanding when to use each will make your AI agent more reliable.

### CLI vs. MCP: which to use

| Scenario | Use CLI | Use MCP |
|---|---|---|
| Cron jobs and scheduled automation | Yes | No |
| AI assistants in conversation (Claude Desktop, etc.) | No | Yes |
| Shell pipeline data processing | Yes | No |
| OpenClaw agents that take actions | No | Yes |
| CI/CD pipelines and deployment scripts | Yes | No |
| Natural-language business queries | No | Yes |
| Bulk data export and reporting | Yes | No |

### Combining CLI and MCP in the same agent

For AI agents that run in an agentic loop (like OpenClaw agents with tool use), the MCP server handles the interactive, conversational actions. The CLI handles the heavy lifting — batch operations, data exports, and scheduled triggers.

Example: An OpenClaw agent that runs nightly and prepares a morning brief for the owner.

```yaml
# openclaw-agent.yaml
name: morning-brief-agent
schedule: "0 6 * * *"  # 6 AM daily

tools:
  - type: bash
    description: "Run hisaabo CLI commands for data collection"
  - type: mcp
    server: hisaabo
    description: "Live business data and actions"

instructions: |
  You are a business intelligence agent for an Indian SMB.
  Every morning at 6 AM, you:
  1. Run `hisaabo dashboard --period this-month --json` to get current month data
  2. Run `hisaabo invoice list --status overdue --json` to check overdue invoices
  3. Run `hisaabo item list --low-stock --json` to check stock levels
  4. Call the hisaabo MCP gst_report tool (report_type: "gstr3b", current month)
     to check GST position and upcoming filing deadlines
  5. Compose a concise morning brief in the owner's preferred format
  6. Send it via the notification webhook

  Keep the brief under 300 words. Highlight anything urgent.
  Use INR formatting (₹). Refer to parties by their short names.
```

### Consuming CLI output as an AI agent tool

If your agent framework supports shell tool execution, you can expose the CLI as a tool:

```typescript
// tools/hisaabo-cli.ts
export const hisaaboCLI = {
  name: "hisaabo_cli",
  description: "Run a hisaabo CLI command and return the JSON output. " +
    "Available subcommands: dashboard, invoice list/get/create, " +
    "party list/get, item list/get, payment list/create, gst summary/export",
  parameters: {
    type: "object",
    properties: {
      command: {
        type: "string",
        description: "The hisaabo command to run, e.g. 'invoice list --status overdue --json'"
      }
    },
    required: ["command"]
  },
  execute: async ({ command }: { command: string }) => {
    const { stdout, stderr } = await exec(`hisaabo ${command}`);
    if (stderr) throw new Error(stderr);
    return JSON.parse(stdout);
  }
};
```

This pattern works well for agents that need to do bulk data processing — pull all overdue invoices, sort them, calculate totals — before taking any action through MCP.

## Cron Job Examples

### Daily morning business snapshot

```bash
# /etc/cron.d/hisaabo
# Environment
HISAABO_API_URL=https://your-hisaabo-instance.com
HISAABO_API_KEY=hisaabo_key_xxxxxxxxxxxxxxxxxx
HISAABO_BUSINESS_ID=biz_xxxxxxxxxxxxxxxxxx

# Daily summary at 8:00 AM
0 8 * * * root hisaabo dashboard --period today --json | \
  jq -r '"Revenue: ₹\(.totalRevenue)\nOutstanding: ₹\(.totalOutstanding)\nOverdue invoices: \(.overdueCount)"' | \
  mail -s "Daily Business Summary" owner@yourbusiness.com

# Overdue invoice alert at 9:00 AM
0 9 * * * root hisaabo invoice list --status overdue --json | \
  jq 'length' | \
  xargs -I{} sh -c '[ {} -gt 0 ] && hisaabo invoice list --status overdue | \
    mail -s "ALERT: {} overdue invoices need attention" owner@yourbusiness.com'
```

### Weekly reports (every Monday at 8 AM)

```bash
0 8 * * 1 root /opt/hisaabo-scripts/weekly-report.sh
```

```bash
#!/bin/bash
# /opt/hisaabo-scripts/weekly-report.sh

WEEK=$(date +%Y-W%V)
REPORT_DIR="/var/reports/hisaabo"
mkdir -p "$REPORT_DIR"

# Collect data
DASHBOARD=$(hisaabo dashboard --period this-week --json)
OVERDUE=$(hisaabo invoice list --status overdue --json)
LOW_STOCK=$(hisaabo item list --low-stock --json)

# Build report
REPORT=$(jq -n \
  --argjson dashboard "$DASHBOARD" \
  --argjson overdue "$OVERDUE" \
  --argjson low_stock "$LOW_STOCK" \
  '{
    week: "'"$WEEK"'",
    revenue: $dashboard.totalRevenue,
    expenses: $dashboard.totalExpenses,
    profit: $dashboard.netProfit,
    overdueCount: ($overdue | length),
    overdueTotal: ([($overdue[].totalAmount | tonumber)] | add // 0),
    lowStockCount: ($low_stock | length),
    lowStockItems: [$low_stock[].name]
  }')

echo "$REPORT" > "$REPORT_DIR/week-$WEEK.json"

# Format and send
echo "$REPORT" | jq -r '
"Weekly Report: \(.week)
━━━━━━━━━━━━━━━━━━━━━
Revenue:  ₹\(.revenue)
Expenses: ₹\(.expenses)
Profit:   ₹\(.profit)

Overdue: \(.overdueCount) invoices (₹\(.overdueTotal))
Low Stock: \(.lowStockCount) items: \(.lowStockItems | join(", "))"
' | mail -s "Hisaabo Weekly Report — $WEEK" owner@yourbusiness.com
```

## Configuration File

The CLI looks for a configuration file at `~/.hisaabo/config.json`. You can also place a project-level config at `.hisaabo.json` in your working directory:

```json
{
  "apiUrl": "https://your-hisaabo-instance.com",
  "defaultBusiness": "biz_xxxxxxxxxxxxxxxxxx",
  "output": {
    "format": "table",
    "color": true,
    "pager": true
  }
}
```

Environment variables override the config file. Command-line flags override environment variables.
